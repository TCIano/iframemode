# 统一响应契约（code / message / data）

模板约定后端统一返回 `{ code, message, data }`：成功（`code === 200`）时 `data` 必存在；失败响应在 `src/utils/request.ts` 拦截器层统一提示并 reject，业务代码拿到的都是成功响应，只需处理成功分支。为此每个 API 函数显式标注 `Promise<TApiResponse<T>>` 返回类型，调用方无需为失败分支写样板。

选此是因为主流后端契约，"同一个接口五种写法"是最大的成本来源；失败统一进拦截器，业务层不含错误分支噪音。代价：后端不遵守契约时需要按模块适配（少见，且适配点集中在拦截器一处，不会散到调用方）。
