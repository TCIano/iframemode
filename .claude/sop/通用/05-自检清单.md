# 自检清单

> 目标：仅保留工具无法强制拦截的约定项，减少冗余检查成本。

---

## 检查时机

**每次完成代码生成 / 修改后**，在输出结果前逐条检查。

## 检查清单

### 约定项（√ 工具无法自动拦截）

- [ ] 文件/组件是否放在正确目录下？
- [ ] 文件名用 camelCase（普通文件）还是 PascalCase（组件）？
- [ ] 组件名是否与文件名一致？
- [ ] 组件职责是否单一？→ 逻辑或布局膨胀时提取 hook 或子组件
- [ ] 组件内是否有直接 `fetch` / `axios` 调用？→ 移到 api 层
- [ ] api 调用是否按模块聚合在对应文件中？
- [ ] 类型定义是否集中在 `types/` 下？→ 不散落各文件
- [ ] 新接口是否继承模块公共基类？→ 禁止重复字段
- [ ] 派生类型用 `Omit`/`Pick`/交叉类型表达差异？→ 不改基类
- [ ] TODO / FIXME 是否全处理完？→ 未完成则在 commit message 说明

### 自动化项（工具已覆盖，不逐条查，提交流程会拦截）

- **ESLint** → `npm run lint` 报错：`any`、`console.log`、`debugger`、未使用变量等
- **TypeScript** → `npm run type-check` 报错：类型标注、泛型缺失等
- **Prettier** → `npm run format` 自动修复：缩进/引号/分号等
- **commitlint** → commit 时自动拦截不规范的 message

---

## 如果检查未通过

先修复再提交：

1. 标记违反的规则
2. 逐一修正
3. 运行 `npm run type-check && npm run lint && npm run format`
4. 全部通过后输出最终结果
