# 自检清单

> 目标：仅保留工具无法强制拦截的约定项，减少冗余检查成本。
> 工具能自动拦截的项不在此列，见 @.claude/sop/通用/09-自动校验规范.md（单一事实源）。

---

## 检查时机

**每次完成代码生成 / 修改后**，在输出结果前逐条检查。

## 检查清单

| #   | 检查项                                                | 违反时看哪                  |
| --- | ----------------------------------------------------- | --------------------------- |
| 1   | 文件/组件放在正确目录？                               | 技术栈/vue-core（目录结构） |
| 2   | 文件名 camelCase（普通）还是 PascalCase（组件）？     | 02-命名规则                 |
| 3   | 组件名与文件名一致？                                  | 02-命名规则                 |
| 4   | 组件职责单一？逻辑/布局膨胀时提取 hook 或子组件？     | 07-组件设计规范 §2 决策树   |
| 5   | 组件内没有直接 `fetch` / `axios` 调用？               | 03-代码约束（代码组织）     |
| 6   | api 调用按模块聚合在对应文件？                        | 06-api设计规范 §3           |
| 7   | 类型定义集中在 `types/` 下？                          | 03-代码约束（文件约束）     |
| 8   | 新类型继承模块公共基类、无重复字段？                  | 03-代码约束（类型约束）     |
| 9   | 派生类型用 `Omit`/`Pick`/交叉类型表达差异？           | 03-代码约束（类型约束）     |
| 10  | 注释符合格式（单行优先、按代码类型、精简）？          | 03-代码约束（注释约束）     |
| 11  | TODO / FIXME 全处理完？未完成则在 commit message 说明 | 03-代码约束（注释约束）     |
| 12  | Store 状态放对层级（local vs store）？                | 08-状态管理规范 §1 决策树   |

> 自动化项（ESLint / TypeScript / Prettier / commitlint）由 09-自动校验规范.md 中的工具覆盖，pre-commit / commit-msg 阶段自动拦截，不在此逐条检查。

---

## 如果检查未通过

先修复再提交：

1. 标记违反的规则
2. 逐一修正
3. 运行 `npm run type-check && npm run lint && npm run format`
4. 全部通过后输出最终结果
