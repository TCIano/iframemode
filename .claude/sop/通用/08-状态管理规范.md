# 状态管理规范

> 目标：解决"什么时候该用全局 store，什么时候用 local state"的决策问题。
> 核心原则：**状态离使用者越近越好，能 local 就别 global。**

---

## 1. 状态分层决策树

```
这个状态只在一个组件内使用？
├── 是 → local ref / useState（永远第一选择）
│
否 → 只在父子组件间传递？
├── 是 → props 透传（≤ 2 层）
│       └─ 透传超过 2 层 → provide/inject 或 Context
│
否 → 在多个无关组件间共享？
├── 缓存服务端数据（用户信息、配置等）→ 全局 store
├── 跨页面状态（当前筛选条件、展开状态）→ 全局 store
└── 临时 UI 状态（弹窗打开/关闭）→ local state（不要进 store）
```

### 核心判断标准

| 状态特征                 | 放哪                                    | 原因                     |
| ------------------------ | --------------------------------------- | ------------------------ |
| 只影响当前组件           | local state                             | 不需要共享，不需要持久化 |
| 父传子 ≤ 2 层            | props 透传                              | 最直观的数据流           |
| 父传子 ≥ 3 层            | provide / Context                       | 避免中间层无用 props     |
| 多个无关组件需要         | 全局 store                              | 数据的唯一可信来源       |
| 页面刷新后还要保留       | 全局 store + 持久化                     | localStorage / cookie    |
| 服务端数据（列表、详情） | 全局 store（可选）或 request 时按需缓存 | 见下方详细规则           |

## 2. 状态分类与处理方式

```
┌─────────────────────────────────────────────────┐
│                   全局 store                      │
│  用户登录态  系统配置  跨页面的筛选/搜索条件        │
│  需要多组件共享的服务端数据                        │
└─────────────────────────────────────────────────┘
                        ↑ 需要共享

┌─────────────────────────────────────────────────┐
│                provide / Context                  │
│  主题  i18n 当前语言  页面级共享状态              │
│  组件子树内共享但不跨子树                         │
└─────────────────────────────────────────────────┘
                        ↑ 需要透传

┌─────────────────────────────────────────────────┐
│                 local state                       │
│  表单输入  弹窗开关  展开/折叠  loading           │
│  组件内部临时 UI 状态                            │
└─────────────────────────────────────────────────┘
```

## 3. 什么时候放全局 store（详细规则）

### ✅ 应该放 store

| 场景           | 例子                         | 原因               |
| -------------- | ---------------------------- | ------------------ |
| 登录态 / Token | currentUser, permissions     | 几乎所有组件都要读 |
| 系统配置       | 侧栏展开/收起、主题色        | 跨页面保持一致性   |
| 跨页面缓存     | 列表的当前筛选条件、Tab 切换 | 回退页时不丢失     |
| 全局通知       | 消息数、待办事项             | 多组件消费         |

### ❌ 不应该放 store

| 场景          | 错误做法   | 正确做法                 |
| ------------- | ---------- | ------------------------ |
| 表单临时输入  | 放进 store | local state，提交时取    |
| 弹窗打开/关闭 | 放进 store | 父组件 local state       |
| 请求 loading  | 放进 store | 每个组件自己的 `loading` |
| 组件内部计算  | 放进 store | `computed` / `useMemo`   |

### ⚠️ 服务端数据（灰色地带）

```
请求的数据要不要进 store？
├─ 只在一个页面用 → 不进 store，组件内请求 + local state
├─ 多个页面/组件用同一个缓存 → 进 store
└─ 不确定 → 先 local，真的需要共享时再升到 store
```

## 4. 全局 Store 设计原则

| 原则                          | 说明                                                            |
| ----------------------------- | --------------------------------------------------------------- |
| **按领域拆分**                | 每个 store 一个领域（user store、report store），不要全局大对象 |
| **最小暴露原则**              | 只暴露外部需要读写的 state 和 action，内部 helper 不导出        |
| **不要在 store 里放 UI 状态** | 弹窗 visible、当前输入值——这些属于组件自身                      |
| **Action 命名带操作意图**     | `fetchUserList`、`setFilterKeyword`，而非 `updateState`         |
| **避免 store 间循环依赖**     | Store A 不要直接读 Store B 的 state，通过事件或父组件协调       |
| **异步操作在 action 里完成**  | Store 封装 API 调用 + state 更新，组件只调用 action             |

## 5. 跨框架对照

| 通用概念    | Vue                          | React                                       |
| ----------- | ---------------------------- | ------------------------------------------- |
| 局部状态    | `ref()` / `reactive()`       | `useState()`                                |
| 计算值      | `computed()`                 | `useMemo()`                                 |
| 子树上下文  | `provide()` / `inject()`     | `createContext()` / `useContext()`          |
| 全局 store  | Pinia (Composition API 风格) | Zustand / Redux Toolkit / Jotai             |
| 异步 action | Pinia action 内直接 await    | Zustand async action / RTK createAsyncThunk |

> 换技术栈时，本文件的决策规则不变，只替换上表的实现工具。
