# 提交规范

> 目标：保持可追溯的 git 历史，方便自动生成 changelog。

---

## Commit Message 格式

```
<type>: <中文简短描述>

<可选的中文详细说明，每行不超过 80 字符>
```

> Commit message 推荐使用**中文**书写（type 保持英文）。`commitlint.config.js` 当前强制校验 type 枚举和提交格式，不校验中文字符。类型列表与配置文件保持一致，两者冲突以配置文件为准。

允许的 type：

| Type       | 用途                           |
| ---------- | ------------------------------ |
| `feat`     | 新功能                         |
| `fix`      | 修复                           |
| `docs`     | 文档                           |
| `style`    | 代码风格（不影响功能）         |
| `refactor` | 重构（既不是新功能也不是修复） |
| `perf`     | 性能优化                       |
| `test`     | 测试                           |
| `chore`    | 构建 / 工具                    |
| `ci`       | CI 配置                        |
| `revert`   | 回滚                           |

示例：

```
feat: 用户列表页增加 avatar 上传功能
fix: 搜索时用户列表分页重置
refactor: 将认证逻辑抽取为 useAuth hook
```

---

## 提交内容原则

**无关紧要的改动不单独成 commit，并入相邻功能改动，commit message 也不提。**

以下改动不应产生独立 commit（合并进相关的功能/修复提交即可）：

- 移除 `console.log` / 注释代码
- 微小的命名调整、格式统一
- lint / prettier 自动修复
- 调整局部变量顺序、补充空行

> 单独提交这类内容会污染 git 历史（产生大量 `chore: 移除打印` 式噪声提交），且 changelog 无法区分主次。
> 例外：全局一次性清理（如整个项目移除废弃 API）可单独 commit，用 `refactor` / `chore` 描述。

**提交粒度**：一个 commit 只做一件事，改动范围与描述一致，不夹带无关改动（如修复 bug 时顺手改了不相干文件的命名）。

---

## 正反例子对比

### 反例（噪声提交 / 描述含糊）

```
chore: 移除打印                  # 无关紧要改动单独提交，噪声
style: 格式化                    # 描述没有信息量，不知道改了什么
feat: 修改一些东西                # 含糊，无法追溯
fix: 修 bug                      # 不知道修了什么、为什么修
fix: 分页重置 + 表单校验 + 命名调整  # 一个 commit 塞多个无关改动
```

### 正例

```
fix: 搜索时用户列表分页重置        # 功能修复，移除打印等已并入
refactor: 将认证逻辑抽取为 useAuth hook
feat: 用户列表页增加 avatar 上传功能
chore: 升级 vite 5.4 修复构建告警
```

> 如果提交内容里既有修复又带清理，把清理部分一起提交，message 只描述主改动；清理内容大到值得单独说明时，用正文说明，不单独成 commit。

## 提交前检查

- `npm run lint` 通过
- `npm run type-check` 通过
- 没有 `console.log`（除 `warn` / `error`）
- 本次提交无无关紧要的噪声改动（见「提交内容原则」）

## 分支命名

```
feat/user-profile
fix/login-bug
refactor/auth-flow
chore/upgrade-deps
```
