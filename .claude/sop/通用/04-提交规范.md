# 提交规范

> 目标：保持可追溯的 git 历史，方便自动生成 changelog。

---

## Commit Message 格式

```
<type>: <中文简短描述>

<可选的中文详细说明，每行不超过 80 字符>
```

> Commit message 使用**中文**书写（type 保持英文）。该格式由 `commitlint.config.js` 自动校验，commit 时不符合会拦截。类型列表与配置文件保持一致，两者冲突以配置文件为准。

允许的 type：

| Type       | 用途                           |
| ---------- | ------------------------------ |
| `feat`     | 新功能                         |
| `fix`      | 修复                           |
| `docs`     | 文档                           |
| `style`    | 代码风格（不影响功能）         |
| `refactor` | 重构（既不是新功能也不是修复） |
| `perf`     | 性能优化                       |
| `test`     | 测试                           |
| `chore`    | 构建 / 工具                    |
| `ci`       | CI 配置                        |
| `revert`   | 回滚                           |

示例：

```
feat: 用户列表页增加 avatar 上传功能
fix: 搜索时用户列表分页重置
refactor: 将认证逻辑抽取为 useAuth hook
```

## 提交前检查

- `npm run lint` 通过
- `npm run type-check` 通过
- 没有 `console.log`（除 `warn` / `error`）
- 没有 TODO / FIXME 未处理（如果是故意的，在 commit message 里注明）

## 分支命名

```
feat/user-profile
fix/login-bug
refactor/auth-flow
chore/upgrade-deps
```
