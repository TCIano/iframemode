# 代码约束

> 目标：用明确禁令和底线规则减少人工 review 成本。

---

## 类型约束

| 规则                                  | 说明                                                                |
| ------------------------------------- | ------------------------------------------------------------------- |
| **禁止使用 `any`**                    | 必须用 `unknown` + 类型守卫代替                                     |
| 类型声明方式                          | 统一使用 `type`，不使用 `interface`                                 |
| 泛型显式声明                          | `ref<T>()`、`reactive<T>()` 在类型无法从初值可靠推断时显式标注，不为自明初值重复声明 |
| 函数返回值必须显式标注                | 除非极其明显（`return boolean` 的简单函数）                         |
| **实体模块提取公共基类**              | 存在稳定公共字段的实体型模块提取 `T{Xx}Base`，供模块实体类型继承；非实体型模块不为规则创建空基类 |
| **优先继承，禁止字段重复**            | 已存在公共字段时，新类型必须继承或复用已有类型，不得复制粘贴字段    |
| **字段增量用 `Omit`/`Pick`/交叉类型** | 派生差异用 `Omit<Base, 'a'> & {a: NewType}` 表达，不改基类          |
| **模块统一前缀**                      | 同模块类型统一前缀，如 `TUserInfo`、`TUserListReq`、`TUserListResp` |

## 代码组织约束

| 规则                             | 说明                                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| **组件内禁止直接写 fetch/axios** | 所有请求走对应的 api 层                                                                    |
| **组件职责单一**                 | 组件只做一件事。逻辑或布局膨胀时提取到 hook 或子组件，在可读性的前提下遵循模块化开发      |
| 静态样式不写 inline style             | 静态样式写入 scoped class；响应式尺寸、CSS 变量等无法由 class 表达的动态样式可用 `:style` |
| **可选 Props 必须提供默认值**    | 使用 `withDefaults` 为可选 Props 提供默认值，必填 Props 无需添加默认值                    |
| Emits 必须类型化                 | 用 `defineEmits<Emit>()`，不要用字符串数组                                                |
| **api 层按模块聚合**             | 每个模块一个 api 文件，所有接口按功能分组，导出命名统一 `Api` 后缀，如 `fetchUserListApi` |
| **类型定义集中管理**             | 模块类型放在 `types/` 下，不分散在各 `.ts` 文件中                                         |

## 注释约束

| 规则                        | 说明                                                                 |
| --------------------------- | -------------------------------------------------------------------- |
| **注释简洁，优先中文**    | 团队业务说明使用中文；协议字段、标准术语与第三方 API 保留其公认英文名称                  |
| **复杂逻辑必须注释**        | 算法、非显而易见的判断条件、时序依赖等必须写注释解释意图             |
| **非必要不注释**            | 代码本身能表达意图的（如 `if (isEmpty(list))`）不加注释，不写废话    |
| **TODO/FIXME 必须带上下文** | 临时标记写明原因和预期方案，`// TODO: 接入真实 API 后替换 Mock 数据` |
| **禁止注释掉的死代码**      | 删除不用代码，不留注释块。需恢复时走 git history                     |

### 注释格式（按代码类型）

注释的要点是**精简**：单行能说清绝不多行，只注释「是什么/为什么」，不注释「怎么做」。

| 代码类型     | 格式                                        | 示例                                                  |
| ------------ | ------------------------------------------- | ----------------------------------------------------- |
| 类型及字段   | TSDoc 单行 `/** ... */`                     | `/** 业务状态码，200 表示成功 */ code: number`        |
| 导出函数     | TSDoc 一句话说明，可推断入参不写 @param     | `/** 获取数据流向列表 */`                             |
| 复杂函数     | TSDoc + `@param`/`@returns`（非显而易见时） | `@param id 记录 ID`（`url`、`params` 之类自明的不写） |
| 复杂逻辑引导 | 逻辑步骤之间用简短 `//` 引导，一步一句      | `// 先按状态过滤，再按页截取`                         |
| 行内解释     | `//` 注释「为什么」非「是什么」             | `// 跨域请求时发送 cookie`（不写 `// 发送 cookie`）   |
| 区块分组     | `// ===== 分组名 =====`                     | `// ===== Mock 数据 =====`                            |
| 临时标记     | `// TODO:` / `// FIXME:` 带上下文           | `// TODO: 接入真实 API 后替换 Mock 数据`              |

- **单行优先**：`/** */` 单行能说清，就不用 `@param`、`@returns` 凑行数
- **复杂逻辑写引导**：在步骤之间用一句 `//` 引导读者跟上流程，而非整段逻辑前堆一大段说明
- **字段注释写「是什么」**：意图/原因留给行内 `//`，避免两层注释重复
- **不逐行注释**：重复模式、可自明代码不注释（对齐「非必要不注释」）
- **统一 `/** \*/`与`//`**：不用 `///`，不用行尾堆大段注释

## 文件约束

| 规则                               | 说明                            |
| ---------------------------------- | ------------------------------- |
| 一个文件导出一个主要实体           | 特殊情况可导出辅助类型          |
| utils 中的纯函数不得包含副作用     | 纯工具函数不调用 API、不读写浏览器存储；请求、鉴权、埋点等基础设施模块可集中封装明确副作用 |
| 非类型文件禁止导出声明文件中的类型 | 在 types/ 中集中定义            |
