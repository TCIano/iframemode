# 代码约束

> 目标：用明确禁令和底线规则减少人工 review 成本。

---

## 类型约束

| 规则                                  | 说明                                                                |
| ------------------------------------- | ------------------------------------------------------------------- |
| **禁止使用 `any`**                    | 必须用 `unknown` + 类型守卫代替                                     |
| 优先用 `interface` 还是 `type`        | 统一使用 `type`（选一个，坚持）                                     |
| 泛型显式声明                          | `ref<T>()`, `reactive<T>()`，不要省略类型参数                       |
| 函数返回值必须显式标注                | 除非极其明显（`return boolean` 的简单函数）                         |
| **每个模块定义公共基类**              | 模块内通用字段提取到 `T{XxModule}Base`，供该模块所有接口继承        |
| **优先继承，禁止字段重复**            | 新接口必须继承已有公共类型，不得复制粘贴已有字段                    |
| **字段增量用 `Omit`/`Pick`/交叉类型** | 派生差异用 `Omit<Base, 'a'> & {a: NewType}` 表达，不改基类          |
| **模块统一前缀**                      | 同模块接口统一前缀，如 `TUserInfo`、`TUserListReq`、`TUserListResp` |

## 代码组织约束

| 规则                               | 说明                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| **组件内禁止直接写 fetch/axios**   | 所有请求走对应的 api/service 层                                                      |
| **组件职责单一**                   | 组件只做一件事。逻辑或布局膨胀时提取到 hook 或子组件，在可读性的前提下遵循模块化开发 |
| 禁止 inline style 写动态样式       | 使用 class 绑定代替                                                                  |
| Props 必须用 withDefaults 给默认值 | 不允许未定义的 props 默认值                                                          |
| Emits 必须类型化                   | 用 `defineEmits<Emit>()`，不要用字符串数组                                           |
| **api 层按模块聚合**               | 每个模块一个 api 文件，所有接口按功能分组，导出命名如 `fetchUserList`                |
| **类型定义集中管理**               | 模块类型放在 `types/` 下，不分散在各 `.ts` 文件中                                    |

## 文件约束

| 规则                               | 说明                            |
| ---------------------------------- | ------------------------------- |
| 一个文件导出一个主要实体           | 特殊情况可导出辅助类型          |
| utils 中的纯函数不得包含副作用     | 不调用 API、不读写 localStorage |
| 非类型文件禁止导出声明文件中的类型 | 在 types/ 中集中定义            |

## ESLint 规则要点

| 规则                   | 说明                                                                             |
| ---------------------- | -------------------------------------------------------------------------------- |
| import 自动排序        | perfectionist 插件，按字母排序，分组（builtin/external/internal/parent/sibling） |
| 未使用变量/import 报错 | `@typescript-eslint/no-unused-vars`，禁止遗留死代码                              |
| 禁止 debugger 语句     | `no-debugger`，不允许调试代码流入生产                                            |
| 禁止显式 `any`         | `@typescript-eslint/no-explicit-any`，必须用 `unknown`                           |
| 禁止空函数             | `no-empty-function`，空函数体必须有注释说明                                      |
| 优先 `===` / `!==`     | `eqeqeq`，禁止 `==` / `!=`（除非前端 `== null` 同时匹配 null/undefined）         |
| 禁止 `console.log`     | 允许 `console.warn` / `console.error`，防止调试日志流入生产                      |

## Stylelint 规则要点

| 规则                      | 说明                                                  |
| ------------------------- | ----------------------------------------------------- |
| 类名格式                  | 默认 `.class-name`（kebab-case），禁止驼峰/下划线类名 |
| 禁止无效选择器/属性       | 不写浏览器不认识的语法                                |
| 禁止重复选择器            | 同一文件中不允许重复定义同一选择器                    |
| 声明顺序                  | 建议按 定位 → 盒模型 → 排版 → 视觉 → 动画 分组        |
| no-descending-specificity | 禁止特异性递减的重复定义                              |
| 颜色值                    | 优先 `#` 十六进制简写，大小写统一                     |

> 以上规则以项目 `stylelint.config.js` 为准，`npm run lint` 包含 Stylelint 检查。

## 格式化约束

优先以项目配置文件为准（不存在时使用下方默认值）：

| 优先级     | 来源          | 文件                    |
| ---------- | ------------- | ----------------------- |
| 高         | Prettier      | `prettier.config.js`    |
| 高         | ESLint        | `eslint.config.js`      |
| 高         | VSCode        | `.vscode/settings.json` |
| 低（默认） | 本 SOP 默认值 | 见下方                  |

**默认格式化规则（仅当项目无 `prettier.config.js` 时生效）：**

| 规则         | 默认值                          |
| ------------ | ------------------------------- |
| 缩进         | 2 空格，禁止 tab                |
| 行尾         | LF（Unix），禁止 CRLF           |
| 尾逗号       | 全开 — 多行对象/数组末尾加逗号  |
| 分号         | 必须加分号                      |
| 引号         | 单引号优先                      |
| 行最大长度   | 100 字符，超长换行              |
| 文件末尾空行 | 保留一个空行                    |
| 箭头括号     | 单参省略括号 `x => x`，多参保留 |

> 运行 `npm run format` 执行 Prettier 格式化，`npm run lint` 执行 ESLint 修复。
