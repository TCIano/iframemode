# 自动校验规范

> 目标：建立反馈闭环——让工具拦截"能做对的"，让自检关注"工具管不了的"。
> 核心原则：**能自动化的一定不手检，不能自动化的按流程检。**

---

## 1. 拦截地图

提交前，问题被拦截在哪个环节一览：

```
你写代码 ─→ Agent 自检 ─→ git add ─→ pre-commit ─→ commit-msg ─→ 推送
                 │              │           │              │
                 ▼              ▼           ▼              ▼
              约定项          ──     ESLint       commitlint
              类型继承        ──     Prettier      格式校验
              目录正确        ──     ──             ──
              职责单一        ──     ──             ──
```

```
┌────────────────────────────────────────────────────────┐
│                各环节捕获的问题类型                       │
├────────────┬────────────────┬───────────┬──────────────┤
│ Agent 自检  │ git add（无）    │ pre-commit │ commit-msg   │
├────────────┼────────────────┼───────────┼──────────────┤
│ 目录放错    │ ──             │ any        │ commit 格式  │
│ 文件名不对  │ ──             │ console.log│              │
│ API 不聚合  │ ──             │ debugger   │              │
│ 类型不继承  │ ──             │ 未用变量   │              │
│ 组件过于臃肿│ ──             │ import 排序│              │
│ Store 设计  │ ──             │ 代码格式   │              │
└────────────┴────────────────┴───────────┴──────────────┘
```

## 2. 自动化拦截（工具已覆盖，无需自检）

| 检查项              | 工具                                 | 拦截时机     | 触发方式                    |
| ------------------- | ------------------------------------ | ------------ | --------------------------- |
| Commit message 格式 | commitlint                           | `commit-msg` | 每次 commit 自动            |
| ESLint 规则         | eslint + lint-staged                 | `pre-commit` | 仅检查 git add 的文件       |
| Prettier 格式化     | prettier + lint-staged               | `pre-commit` | 仅检查 git add 的文件       |
| `any` 类型          | `@typescript-eslint/no-explicit-any` | `pre-commit` | 自动拦截                    |
| `console.log`       | ESLint 规则                          | `pre-commit` | 自动拦截（warn/error 放行） |
| `debugger`          | ESlint `no-debugger`                 | `pre-commit` | 自动拦截                    |
| import 排序         | perfectionist + lint-staged          | `pre-commit` | 自动排序                    |
| 未使用变量/import   | `no-unused-vars`                     | `pre-commit` | 自动拦截                    |

> 运行 `npm run lint` 也可以手动触发 ESLint 检查全部文件。

## 3. 约定项自检（工具无法自动拦截）

05-自检清单 中的**约定项**需要 Agent 或人工关注：

| 约定项                | 为什么工具拦不了                                         | 如何检查                     |
| --------------------- | -------------------------------------------------------- | ---------------------------- |
| 文件/组件放在正确目录 | 取决于业务语义，工具不知道"report 属于 api/ 还是 views/" | 看目录结构约定               |
| 组件职责单一          | 行数阈值可以拦，但"职责"是语义概念                       | 看 07-组件设计规范 §2 决策树 |
| API 按模块聚合        | 工具只知道文件存在，不知道是否该合到同一个模块           | 看 06-api设计规范 §3         |
| 新接口继承基类        | 未继承不会报错，工具不能要求必须继承某类型               | 看 03-代码约束 §类型约束     |
| Store 设计合理        | 放 local 还是 store 是设计决策                           | 看 08-状态管理规范 §1 决策树 |

## 4. CI 校验（推荐）

> 当前模板项目未配置 CI，以下为推荐配置，接入时参考。

| 阶段        | 检查内容               | 参考命令                         |
| ----------- | ---------------------- | -------------------------------- |
| lint        | ESLint + Prettier      | `npm run lint && npm run format` |
| type-check  | TypeScript 类型检查    | `npm run type-check`             |
| build       | 确保构建不中断         | `npm run build`                  |
| commit lint | 确保合并的 commit 合规 | `npx commitlint --from HEAD~5`   |

推荐 GitHub Actions / GitLab CI 配置：

```yaml
# .github/workflows/ci.yml
steps:
  - run: npm ci
  - run: npm run lint
  - run: npm run type-check
  - run: npm run build
```
