# 自动校验规范

> 目标：建立反馈闭环——让工具拦截"能做对的"，让自检关注"工具管不了的"。
> 核心原则：**能自动化的一定不手检，不能自动化的按流程检。**

---

## 1. 拦截地图

提交前，问题被拦截在哪个环节一览：

```
你写代码 ─→ Agent 自检 ─→ git add ─→ pre-commit ─→ commit-msg ─→ 推送
                 │              │           │              │
                 ▼              ▼           ▼              ▼
                  约定项          ──     ESLint       commitlint
                  类型继承        ──     Prettier      格式校验
                  目录正确        ──     Stylelint     ──
                  职责单一        ──     ──             ──
```

```
┌────────────────────────────────────────────────────────┐
│                各环节捕获的问题类型                       │
├────────────┬────────────────┬───────────┬──────────────┤
│ Agent 自检  │ git add（无）    │ pre-commit │ commit-msg   │
├────────────┼────────────────┼───────────┼──────────────┤
│ 目录放错    │ ──             │ any        │ commit 格式  │
│ 文件名不对  │ ──             │ console.log│              │
│ API 不聚合  │ ──             │ debugger   │              │
│ 类型不继承  │ ──             │ 未用变量   │              │
│ 组件过于臃肿│ ──             │ import 排序│              │
│ Store 设计  │ ──             │ 代码/样式格式│              │
└────────────┴────────────────┴───────────┴──────────────┘
```

## 2. 自动化拦截（工具已覆盖，无需自检）

| 检查项              | 工具                                 | 拦截时机     | 触发方式                                    |
| ------------------- | ------------------------------------ | ------------ | ------------------------------------------- |
| Commit message 格式 | commitlint                           | `commit-msg` | 每次 commit 自动                            |
| ESLint 规则         | eslint + lint-staged                 | `pre-commit` | 暂存区文件，自动修复后校验                       |
| Prettier 格式化     | prettier + lint-staged               | `pre-commit` | 暂存区文件，自动格式化                           |
| Stylelint 校验      | stylelint + lint-staged              | `pre-commit` | 暂存区样式文件，自动修复后校验                   |
| BEM 类名            | `selector-class-pattern`             | `pre-commit` | 自动拦截                                    |
| `any` 类型          | `@typescript-eslint/no-explicit-any` | `pre-commit` | 自动拦截                                    |
| `console.log`       | ESLint `no-console`                  | `pre-commit` | 拦截，允许 `console.warn` / `console.error` |
| `debugger`          | ESlint `no-debugger`                 | `pre-commit` | 自动拦截                                    |
| import 排序         | perfectionist + lint-staged          | `pre-commit` | 自动排序                                    |
| 未使用变量/import   | `no-unused-vars`                     | `pre-commit` | 自动拦截                                    |

> `pre-commit` 不执行 TypeScript 类型检查。提交前请运行 `npm run type-check`；CI 或构建阶段必须再次执行类型检查。
>
> 运行 `npm run lint` 执行 ESLint + Stylelint 自动修复；`npm run lint:check` 只检查不修改；`npm run lint:style` 仅自动修复样式。`npm run format` 自动格式化，`npm run format:check` 只检查格式。

## 3. 约定项自检（不在此列）

工具无法自动拦截的**约定项**（目录正确、职责单一、API 聚合、类型继承、Store 设计）统一收敛在 @.claude/sop/通用/05-自检清单.md，输出代码后逐条检查。本文件只管工具能自动拦截的部分，避免两份清单漂移。

## 4. CI 校验（推荐）

> 当前模板项目未配置 CI，以下为推荐配置，接入时参考。

| 阶段        | 检查内容                      | 参考命令                         |
| ----------- | ----------------------------- | -------------------------------- |
| lint        | ESLint + Stylelint                  | `npm run lint:check`             |
| format      | Prettier 纯检查                     | `npm run format:check`           |
| type-check  | TypeScript 类型检查           | `npm run type-check`             |
| build       | 确保构建不中断                | `npm run build`                  |
| commit lint | 确保合并的 commit 合规        | `npx commitlint --from HEAD~5`   |

推荐 GitHub Actions / GitLab CI 配置：

```yaml
# .github/workflows/ci.yml
steps:
  - run: npm run lint:check
  - run: npm run format:check
  - run: npm run type-check
  - run: npm run build
```
