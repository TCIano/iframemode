# 对话规范（A 面：人与 Agent 的协作协议）

> 目标：建立一套可复现的对话流程，减少"每次重新教一遍"的损耗。
> 核心原则：**先贴规则，再给任务，最后给验收条件。**

---

## 1. 任务下发流程

### 触发条件：给 Agent 下新任务时

**必须做的三步：**

```
步骤 1 — 指明上下文
  "当前项目是 iframeMode-template，请先读 @.claude/CLAUDE.md"

步骤 2 — 指明本次任务应参考的 SOP
  "本次涉及命名，请遵循 @.claude/sop/通用/02-命名规则.md"

步骤 3 — 说清楚：目标 + 约束 + 验收条件
  ❌ 差："帮我写个表格组件"
  ✅ 好："创建 src/components/BasicTable.vue，展示用户列表。
          - 列定义从 props 传入
          - 使用 Ant Design Vue 的 <a-table>
          - 支持分页（pageSize 默认 10）
          - 验收：跑完 npm run build 无报错"
```

### 触发条件：任务涉及多个步骤

**拆成 3-5 步，一次只下 1-2 步指令：**

- 第 1 轮："先设计组件接口（props/emits/暴露的方法），给我看一下"
- 第 2 轮："按设计实现，完成后跑 npm run lint"
- 第 3 轮："跑 npm run type-check，确保无类型错误"

> 注意：不要一次性丢 5 个以上的独立需求，会让 Agent 遗漏。

## 2. 上下文传递规范

### 必须传递的信息

| 信息       | 怎么说                                            |
| ---------- | ------------------------------------------------- |
| 技术栈背景 | "项目是 Vue 3 + TS + Ant Design"                  |
| 相关规则   | "看一下 03-代码约束.md，特别注意禁止 any"         |
| 相关文件   | "参考 src/components/BasicForm.vue 的写法"        |
| 验收条件   | "完成后 npm run build && npm run type-check 通过" |

### 反例对照

| 不要这样做         | 改这样                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| "帮我封装一下请求" | "在 src/api/user.ts 里添加 getUserList API，走 @.claude/sop/技术栈/vue-ant-design.md 的 HTTP 规范"                     |
| "改一下这个组件"   | "把 BasicTable.vue 的 loading 状态加上，用 Ant Design 的 `<a-spin>`，参考现有组件的实现模式"                           |
| "这里有个 bug"     | "复现路径：打开 /user/list 页面，点击第二页。期望：表格切换到第二页。实际：控制台报 TypeError。先排查原因再给修复方案" |

## 3. 反馈闭环规范

### 触发条件：Agent 输出代码后

1. **让 Agent 先自我检查**（见 `05-自检清单.md`）
2. **你再做快速验收**（只看逻辑，不管格式）
3. **发现问题时指出"违反了什么规则"**，而不是只说"改一下"

```
❌ "loading 状态没加"
✅ "违反了 03-代码约束.md：loading 状态必须统一使用 useLoading hook"
```

### 触发条件：Agent 连续犯同一类错

把这次错误抽象成一条新规则，补充到对应的 SOP 文件里。

```
发现场景：Agent 连续两次在组件内直接写 fetch
处理方式：在 03-代码约束.md 里加一条 "禁止在组件内直接调用 fetch/axios"
```

> 这样 SOP 就变成了一个有生命力的进化文档，而不是写一次就落灰。

## 4. 对话风格约定

| 场景   | 建议                              |
| ------ | --------------------------------- |
| 下任务 | 分点编号，明确优先级              |
| 给反例 | 先给"不要这样"再给"应该这样"      |
| 验收   | 指出具体行号和违反的规则          |
| 修正   | 告诉 Agent 原因，而不是只告诉结果 |
