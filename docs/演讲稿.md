# iframeMode-template 项目介绍演讲稿

各位好，今天想和大家介绍的是 **iframeMode-template**：一个面向企业后台场景的 Vue 3 前端模板。

在企业项目中，我们经常会遇到两个看似简单、实际却很耗时的问题：第一，如何让团队从第一天开始就遵循统一的工程规范；第二，如何在功能不断增加时，依然保持代码可维护、可测试、可交接。

iframeMode-template 的目标，就是把这些基础能力提前沉淀好，让团队把精力放在业务本身，而不是反复搭建脚手架、统一目录或补齐工程配置。

这个模板以 Vue 3 和 TypeScript 为核心，采用 Composition API 与 `script setup` 的开发方式。在界面层，我们使用 Ant Design Vue；在状态管理方面使用 Pinia；路由采用 Hash 模式；图表能力则基于按需注册的 ECharts。它既能覆盖常见的管理后台需求，也尽量避免为了“完整”而引入不必要的复杂度。

项目结构也围绕职责边界设计：`api` 负责接口模块，`stores` 负责共享状态，`views` 对应页面，`components` 放置通用组件，`hooks` 沉淀可复用的组合逻辑。这样的分层让新成员可以快速定位代码，也让后续的维护和重构更有把握。

为了保证接口调用的一致性，我们在请求层统一约定了返回数据、错误信息以及 401 和 403 等常见状态的处理方式。对于图表场景，项目只注册实际使用的 ECharts 模块，帮助控制最终体积。

工程质量同样是这个模板的重要部分。项目提供 ESLint、Stylelint 和 Prettier 来保持代码风格统一；结合 Husky、lint-staged 与 commitlint，让质量检查自然融入日常开发流程。单元与组件测试使用 Vitest 和 Vue Test Utils，端到端测试使用 Playwright，使关键流程可以获得更完整的验证。

另外，模板内置了 API、页面和组件的生成命令。它们的价值不只是少写几行文件，而是确保每一处新增代码都遵循同一套目录和命名约定。规范不再只是一份文档，而是成为开发流程的一部分。

当然，模板不是为了限制开发者。它提供的是一个稳定起点：清晰的边界、可靠的工具链和可持续演进的规范。团队可以在此基础上按业务需要扩展，而不必每个项目都从零解决同样的问题。

最后，用一句话概括 iframeMode-template：它希望把企业前端开发中重复、容易出错的基础工作标准化，让我们更快、更稳地交付真正有价值的业务功能。

谢谢大家。
